# Обновление 8.3: исправление поиска на Render

Версия 8.3 устраняет ошибочное сообщение «ничего не найдено» при сетевом тайм-ауте, сокращает число запросов и пробует два независимых бесплатных поисковых источника. Если Render всё равно не получает ответ, доступны ссылки для поиска в браузере. OCR, Dockerfile и состав зависимостей не изменены.

**Для перехода с 8.2 достаточно заменить `app.py` и `templates/index.html`.**

**Ограничение:** бесплатный автоматический поиск `ddgs` не имеет гарантированной доступности на облачном хостинге. Этот выпуск не гарантирует успешный поиск при блокировках сетей провайдеров.

# Документы качества — ONLINE 8.2 / бесплатный RapidOCR (исправление сборки)

Сайт для поиска сертификатов соответствия, деклараций, паспортов качества, протоколов испытаний на материалы и анализа загруженных PDF. Работает с любого устройства по ссылке после публикации на Render.

## Исправление Render 8.2

В версии 8.1 запуск `warm_ocr.py` из Docker под `appuser` приводил к `PermissionError` при сохранении ONNX-модели в системную папку RapidOCR. Исправлено только в `Dockerfile`: прогрев выполняется во время сборки с правами на запись, после чего сайт запускается с ограниченными правами. Это не новый OCR-движок и не добавление нагрузки в работающий сервер.

## Что изменилось с версии 7.0

- **Удалены Google Gemini, ключ GEMINI_API_KEY и отправка документа на внешний сервис ИИ.**
- **Добавлен бесплатный OCR RapidOCR**, применяющий модель `cyrillic_PP-OCRv5_rec_mobile` для русского текста. Модель загружается **при сборке Docker**; отсутствие доступа к модели проявится ошибкой публикации, а не незаметно пустыми полями.
- Из текстовых PDF программа читает встроенный текст PyMuPDF. Из сканов — первые три страницы через RapidOCR. Итоговый текст анализируется правилами по наименованию материала, номеру документа, дате и изготовителю.
- Сохранились четыре поля в результате и Excel: **Наименование материала | Номер документа | Дата документа | Производитель**. Если номер не удалось подтвердить по тексту, указывается `б/н`. Для дат — `20.05.2026г.` либо `с 20.05.2026г. по 19.05.2028г.`; неизвестные значения не подставляются из поискового запроса.
- Сохранился поиск доступных PDF и возможность загрузить свой PDF с компьютера (до 25 МБ). Поисковые PDF ограничены **6 МБ**, чтобы не исчерпать память бесплатного сервера. Внешние результаты показываются, только если PDF удалось скачать и разобрать; каталоги исключаются.

## Публикация на Render

1. Распакуйте архив. Откройте ваш репозиторий GitHub и **удалите** старый `ai_extractor.py` (его больше нет).
2. Замените `app.py`, `extractor.py`, `Dockerfile`, `requirements.txt`, `render.yaml`, `templates/index.html`. Добавьте `local_ocr.py`, `warm_ocr.py`.
3. В Render → Environment удалите `GEMINI_API_KEY` и другие ключи, относящиеся к Gemini. Они больше не используются. Пароль `SITE_PASSWORD` и ключ поисковика `BRAVE_SEARCH_API_KEY` можно сохранить.
4. В Render → Deploys запустите **Manual Deploy → Deploy latest commit** (если автодеплой не включён). Тип сервиса должен быть **Docker**.
5. Сборка проверяет, что RapidOCR действительно смог прочитать тестовую строку с кириллицей. При ошибке сборки посмотрите лог Docker Build: наиболее вероятна недоступность сервера с моделью или несовместимость зависимости. Исправлять нужно проблему в сборке, а не токен Gemini.
6. После публикации откройте `https://<ваш-сайт>/health`. Должен быть `version: quality-docs-v8` и объект `recognition` с `provider: RapidOCR + PP-OCRv5 Cyrillic (локально)`. Поле `configured: true` означает установленные компоненты; `ready: true` появится после первого запроса распознавания в запущенном процессе.
7. Загрузите реальный скан PDF, нажмите **Распознать документ**. Сверьте полученные поля с оригиналом.

## Что важно знать

- **Без API-ключа и без оплаты за отдельные распознавания**, но Render может потребовать более производительный тариф из-за памяти/CPU. На Free доступно **512 МБ ОЗУ**: работа OCR на нём **не подтверждена** и может быть медленной или приводить к перезапуску процесса. Для стабильной эксплуатации более подходящим может оказаться сервер с 2 ГБ памяти.
- Модель RapidOCR — распознавание символов, **не языковая модель**. Точность выделения реквизитов зависит от компоновки PDF. Не всякий скан можно достоверно распознать. Сведения необходимо сверять перед применением в ИД.
- Проверяются первые **три страницы** скана (для уменьшения нагрузки). Многостраничный паспорт с изготовителем на четвёртой странице может остаться неполным. Для текстовых PDF читаются все страницы до 200.
- PDF не передаётся в Google или другой OCR API, но файлы по-прежнему проходят через ваш сервер Render. Доступ к ним возможен через временные ссылочные токены в рамках срока кэша. Для чувствительных документов настройте `SITE_PASSWORD`.
- Бесплатный интернет-поиск `ddgs` не гарантирует выдачу. Если он не работает, можно настроить `BRAVE_SEARCH_API_KEY` (поисковый API — отдельная услуга). Недоступные и некорректные PDF скрываются.

## Проверки проекта

`python tests/check_v8_offline.py` — локальная интеграционная проверка: формирование настоящего сканированного PDF, растеризация страницы, передача изображения в **тестовый двойник OCR**, извлечение четырех реквизитов и дат. Также проверены б/н и отбор каталога.

**Ограничение проверки:** в среде сборки доступ к PyPI/ModelScope закрыт, поэтому настоящий движок RapidOCR и модель кириллицы здесь не загружались. Нельзя обещать, что распознавание заработает на Render без итоговой проверки. Это новая, технически обоснованная реализация, а не подтвержденная пользователем исправленная версия.
