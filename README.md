# Документы качества — онлайн-сайт

Готовая версия для публикации в интернете. После разового размещения на хостинге сайт работает по HTTPS-ссылке **без установки Python, BAT-файлов и программ на компьютерах пользователей**.

## Назначение

Пользователь вводит название материала (например, «Арматура А500 Ø18 мм»), выбирает тип документа, при необходимости указывает изготовителя и ГОСТ/ТУ. Сайт ищет доступные PDF и ссылки на документы, пытается прочитать название материала, вид документа, регистрационный номер, дату, срок действия, изготовителя, ГОСТ/ТУ и свойства PDF. Поддерживает OCR первых двух страниц сканов на сервере (при поиске автоматически для первого PDF, для остальных — по кнопке повторного чтения) и выгрузку таблицы в Excel.

### Ограничения

- Совпадение слов и характеристик **не подтверждает действительность сертификата, декларации, применимость к фактической партии**. Проверять документы необходимо в официальных реестрах и у изготовителя.
- Поисковая система не гарантирует выдачу нужного документа: некоторым сайтам недоступно скачивание PDF; некоторые файлы состоят из изображений, с которыми OCR может ошибаться.
- Без `BRAVE_SEARCH_API_KEY` поиск использует неофициальный движок `ddgs`; на хостингах он может временно блокироваться или выдавать неполные результаты. Для стабильного поиска можно подключить официальный Brave Search API (ключ берётся отдельно, возможна платная подписка). Ключ не обязателен для публикации сайта.
- При загрузке собственного PDF файл **передаётся на сервер** для временной обработки, не сохраняется в каталоге сайта. Серверные библиотеки могут временно использовать служебный диск. Не загружайте конфиденциальные документы в публичный сервис без оценки требований к их обработке.
- Для экономии ресурсов у публичной версии есть ограничения: размер PDF до 10 МБ, анализ до 6 найденных PDF за один поиск, OCR до двух страниц, автоматическое OCR только для первого PDF в поиске, для остальных — кнопка «Повторно прочитать PDF», лимиты частоты обращений.

## ОПУБЛИКОВАТЬ САЙТ (один раз, без установки ПО)

### 1. Создайте репозиторий GitHub

1. Откройте https://github.com/new и войдите/зарегистрируйтесь.
2. Введите название `dokumenty-kachestva`, выберите **Private** (если он будет доступен Render вашему аккаунту), создайте репозиторий.
3. На странице нового репозитория нажмите **uploading an existing file** (или **Add file → Upload files**).
4. Перетащите **содержимое** папки архива: `app.py`, `Dockerfile`, `render.yaml`, `requirements.txt`, папку `templates` и остальные файлы. Убедитесь, что `app.py` расположен **в корне** репозитория, а не внутри дополнительной вложенной папки. Подтвердите **Commit changes**.

### 2. Запустите сайт на Render

1. Откройте https://dashboard.render.com/ и войдите/зарегистрируйтесь.
2. Нажмите **New → Web Service**. Подключите свой GitHub и выберите репозиторий `dokumenty-kachestva`.
3. Для приложения выберите **Docker** как Runtime (Render распознает `Dockerfile`), тариф **Free** (если доступен). Команды установки и запуска вручную вводить не требуется, они определены в Dockerfile.
4. Нажмите **Deploy Web Service / Create Web Service** и дождитесь статуса **Live**.
5. Скопируйте фактический HTTPS-адрес, который **Render выдаст вашему сервису** (обычно домен `*.onrender.com`). Этот адрес можно открыть с любого телефона или компьютера.

Другой вариант: **New → Blueprint** и указать GitHub-репозиторий. Файл `render.yaml` задаёт Free Web Service и Docker-конфигурацию. Интерфейс Render может меняться; при публикации следуйте надписям на экране.

### 3. По желанию — пароль для доступа

В Render → **Environment → Add Environment Variable** установите `SITE_PASSWORD` со своим паролем. После сохранения откройте сайт в браузере и введите пароль в стандартном окне. Не добавляйте пароль в GitHub, `README.md`, файлы `.env` или HTML. Если пароль не задан, сайт открыт всем, у кого есть ссылка.

Для более стабильного поиска (дополнительно) добавьте туда `BRAVE_SEARCH_API_KEY`. API-ключ выдаёт Brave Search API: https://api.search.brave.com — это отдельный сервис. Не публикуйте его в GitHub.

## Особенности бесплатного хостинга Render

Бесплатный сервер «засыпает» после 15 минут простоя; при следующем открытии запуск может занимать около минуты. Есть лимиты ресурсов. Изменения файлов на временном диске не сохраняются после перезапуска (сайт не использует этот диск для хранения результатов). Для постоянной работы без ожидания можно использовать платный хостинг. Условия https://render.com/docs/free.

## Обновление сайта

После изменений в файлах GitHub Render обычно запускает пересборку автоматически. Пользователи продолжают открывать тот же адрес. Если меняется код приложения, сам Python на компьютеры посетителей не устанавливается.

## Устранение неполадок

- Сайт открылся, но нет документов: проверить предупреждения внизу результатов, работоспособность поиска `ddgs`; при необходимости подключить `BRAVE_SEARCH_API_KEY`.
- В PDF реквизиты не найдены: проверить сам PDF; файл мог быть сканом/с нестандартной вёрсткой; OCR проверяет первые две страницы.
- `429`: превышен лимит частоты или сервер занят; повторите поиск позже.
- `503` / долгое открытие после простоя: проверьте вкладку **Logs** сервиса на Render.
- `401`: сервер защищён паролем `SITE_PASSWORD` — введите пароль.
- Если в логах ошибка установки: проверьте, что `Dockerfile`, `requirements.txt`, `app.py`, папка `templates/` сохранены в корне репозитория.

## Для инженеров

Ключевые пути: `/` — сайт; `/api/search` — поиск; `/api/upload` — временная обработка загруженного PDF; `/api/inspect` — повторная загрузка PDF с подписанной ссылкой, полученной при поиске; `/api/export` — Excel; `/health` — проверка состояния сервера. Приложение не содержит ключей пользователей и не сохраняет загруженные файлы.

### Локальные тесты разработчика

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Публиковать код **необязательно в открытом репозитории**; Render поддерживает подключение приватных GitHub-репозиториев после авторизации.
